# 團隊分工與成員 C 工作範圍

## 文件用途

本文件保存「團購 AI 選品系統」7 週工程排程的團隊分工，以及使用者在目前對話中確認的成員 C 實際工作範圍，供後續新對話延續專案背景。

原始分工表：`團購AI選品系統_v5_7週工程排程.html`。

## 團隊角色

- 成員 A：後端主力，負責 Auth、資料庫、CRUD API、審核與設定 API、部署支援。
- 成員 B：後端核心引擎，負責 Scoring、Google Trends、TrendSyncJob、AI Summary、排行邏輯及穩定化。
- 成員 C：前端主力，負責頁面架構、UI／UX、響應式設計、前端狀態呈現與頁面互動。
- 成員 D：前端／整合，負責 Mock Server、測試案例、整合測試、文件與 Demo 準備。

## 成員 C 原始 7 週排程

- W1：前端專案骨架、路由、登入頁 UI、JWT 儲存。
- W2：Dashboard 儀表板頁面骨架。
- W3：品項管理頁 CRUD 串接、RoleGuard 前端邏輯。
- W4：品項管理頁 UI、核心客群設定下拉選單 UI。
- W5：品項詳情頁初版，包括因子拆解與 AI 摘要區塊。
- W6：AI 選品與權重合併頁，包括排行、權重、客群設定、審核快速操作；Dashboard Top 10 預覽。
- W7：品項詳情頁完整整合，包括審核表單與趨勢圖；趨勢分析頁，包括手動同步與顯示時間。

## 使用者確認後的成員 C 實際範圍

使用者是成員 C，主要負責前端 UI／UX。現階段後端資料庫尚未接入，且使用者明確要求不進行 API 串接。

目前實作原則：

- 先完成前端網頁框架、頁面骨架、視覺樣式、響應式設計與互動流程。
- 使用本地 Mock 資料展示畫面與狀態，不呼叫後端 API。
- Mock Auth 僅用於前端角色與路由展示，不視為正式登入或 JWT 串接。
- Dashboard 範圍包含統計卡片、Top 10、風險區塊與本地 Mock 資料。
- 每個主要頁面或流程必須考慮四大 UI 狀態：Default、Disabled／Locked、Loading／Pending、Edge Case／Error。
- API、資料庫、真實 JWT、HTTP 錯誤與後端整合不列入成員 C 現階段驗收；待其他成員完成後再進行整合驗收。

## 優先順序說明

原始排程中「JWT 儲存」「CRUD 串接」等工作與使用者目前確認的範圍有衝突。後續工作應以使用者目前明確要求為準：成員 C 只完成前端 UI／UX 與本地 Mock 行為，不主動實作 API 串接。

若使用者未來明確變更分工或要求進入整合階段，再依最新要求更新本文件。
